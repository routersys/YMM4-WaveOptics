# SpectralConvolution for YMM4

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)

---

YMM4 のプラグインが、画像とカーネルの畳み込みを、CPU と GPU で同じ手順で計算するためのライブラリです。
画像を正方形のタイルに分け、高速フーリエ変換で畳み込みます。あわせて、その計算の誤差の上限を求める機能も持ちます。
計算をどちらで行うかの選択と、GPU の結果の判定は行いません。
今は Wave Optics のリポジトリの中に置いています。ほかのプラグインでも使うようになったら、別のリポジトリへ移します。

## 概要

畳み込みは、元の画像の各画素の値を、周りの画素の値の重み付きの和に置き換える計算です。以下では、元の画像を素材と呼びます。重みを正方形に並べたものをカーネルと呼びます。カーネルの半径を r とすると、正方形の一辺は 2r + 1 画素です。src は素材の値、k はカーネルの値です。d は、縦と横がそれぞれ -r〜r の範囲の 2 次元のずれです。本ライブラリは、出力の画素 p の値を式 (1) で求めます。

```
out(p) = Σ_d src(p + d) × k(d)    (1)
```

数学の定義の畳み込みは src(p - d) を使うので、式 (1) とはカーネルの向きが逆です。src(p + d) を使う式 (1) の計算は、数学では相互相関と呼ばれます。本ライブラリでは、この計算を畳み込みと呼びます。型の名前の `DirectCorrelation` は、相互相関を表しています。左右か上下に非対称なカーネルを渡すときは、向きに注意してください。

本ライブラリが扱うのは、次の 3 つです。

- 畳み込みを、CPU と GPU で同じ手順で計算すること
- その計算の誤差の上限を求めること
- GPU の結果を確かめる検査と、自己試験の検査を作ること

以下では、CPU で計算する道筋を CPU の経路、GPU で計算する道筋を GPU の経路と呼びます。

検査は、GPU の結果から求めた測定値を参照値と比べ、差が許容値に収まるかを見るものです。検査 1 件は `ConvolutionMeasurement` で表し、名前、測定値、参照値、許容値を持ちます。測定値と参照値の差の絶対値が許容値以下なら合格で、`Passes` が真になります。自己試験は、決まった模様と決まったカーネルを GPU で畳み込み、その結果から検査を作る処理です。

計算をどちらで行うかの選択、検査の合否による判定、異常の報告は扱いません。Wave Optics では、これらを [YMM4-ComputeGuard](https://github.com/routersys/YMM4-ComputeGuard) が受け持ちます。Wave Optics は、[WaveOpticsCompute.cs](../WaveOptics/Rendering/WaveOpticsCompute.cs) の `ToCheck` で、本ライブラリの `ConvolutionMeasurement` を YMM4-ComputeGuard の `ComputeCheck` に変換し、YMM4-ComputeGuard の判定へ渡します。本ライブラリは YMM4-ComputeGuard を参照しません。

GPU の計算には、C# で書いた計算シェーダーを Direct3D 12 で動かすライブラリである [ComputeWeave](https://github.com/routersys/ComputeWeave) を使います。

## 導入方法

プラグインのプロジェクトで、`SpectralConvolution.props` を読み込みます。

```xml
<Import Project="..\SpectralConvolution\SpectralConvolution.props" />
```

フォルダーは、次のとおりです。

```
SpectralConvolution/                      外側
  README.md
  SpectralConvolution.props
  SpectralConvolution/                    内側。ソース
  SpectralConvolution.Tests/              単体試験
```

`SpectralConvolution.props` が指すのは、内側の `SpectralConvolution` フォルダーです。その中のソースが、プラグインのアセンブリに取り込まれます。現在は、Wave Optics のリポジトリにあります。ほかのプラグインで使うときは、外側の `SpectralConvolution` フォルダーをそのプラグインのリポジトリへコピーし、`Import` のパスを合わせます。プラグインのプロジェクトには、次の設定が要ります。

| 設定 | 理由 |
|---|---|
| ComputeWeave 2.6.0 の NuGet パッケージを参照する | GPU のシェーダーと、`Float2` などの型を使うため。シェーダーは、ComputeWeave のソースジェネレーターがプラグインのビルドの中で作る |
| `AllowUnsafeBlocks` を `true` にする | ComputeWeave のソースジェネレーターが求めるため |
| `ImplicitUsings` を `enable` にする | ソースが `System.Threading` などの名前空間を `using` なしで使うため |
| `Nullable` を `enable` にする | ソースが null 許容の注釈を使うため。`disable` にすると警告が出る |

取り込んだ型はどれも `internal` で、プラグインのアセンブリの外からは見えません。

## 使い方

本ライブラリの主な型は、次のとおりです。

| 型 | 役割 |
|---|---|
| `TilePlan` | 畳み込む範囲のタイルへの分け方 |
| `KernelSpectrum` | 和を 1 にそろえたカーネルと、タイルの大きさに合わせた回転因子とスペクトル |
| `CpuTileConvolver` | CPU の経路の畳み込み |
| `GpuTileConvolver` | GPU の経路の資源と、ComputeWeave のコンテキストへの記録 |
| `GpuTileJob` | GPU の経路の 1 回分の畳み込みの設定。`GpuTileConvolver.Prepare` が返す |
| `GpuTileCheck` | GPU が書き出した値から作る検査 |
| `ConvolutionMeasurement` | 検査 1 件 |
| `SpectralSelfTest` | 決まった模様と決まったカーネルで GPU を確かめる自己試験 |
| `ConvolutionBound` | 誤差の上限 |
| `DirectCorrelation` | 式 (1) を倍精度でそのまま足し合わせる計算。検査の参照値に使う |
| `TileInput` | タイルが読む素材の 2 ノルム。8 ビットの値を 255 で割った値で求める |
| `FastFourierTransform` | 倍精度の高速フーリエ変換。カーネルのスペクトルに使う |

表の 2 ノルムは、素材の 8 ビットの値を 255 で割った値の 2 乗の和の平方根です。赤と緑、青と不透明度の 2 組ごとに求めます。スペクトルは、カーネルを高速フーリエ変換した値です。回転因子とスペクトルは、[タイルに分けた畳み込み](#1-タイルに分けた畳み込み)で説明します。

カーネルのスペクトルは、カーネルの値か半径、タイルの一辺 T が変わったときだけ作り直します。

```csharp
var spectrum = new KernelSpectrum();
spectrum.Update(kernel, radius, TilePlan.SelectSize(radius));
var plan = TilePlan.Create(radius, regionX, regionY, regionWidth, regionHeight);
```

`kernel` は、一辺 2r + 1 の正方形を行ごとに並べた `double` の配列です。`radius` は、カーネルの半径 r です。`kernel` の値は 0 以上の有限の数で、値の和は 0 より大きくなければなりません。`KernelSpectrum` は、値を和で割ってから使います。

畳み込む範囲は、出力を求める矩形です。`regionX` と `regionY` はその左上の座標で、`regionWidth` と `regionHeight` は幅と高さです。座標系は呼び出し側が決めます。CPU の経路の出力の配列と、GPU の経路の出力のテクスチャは、この範囲の大きさにします。範囲は、0 でない素材の画素を囲む矩形を、上下左右に少なくとも r 画素ずつ広げたものにしてください。これより狭いと、総和の検査が正常な GPU でも不合格になることがあります。詳しくは[検査の材料と検査](#5-検査の材料と検査)にあります。素材の外は 0 として扱うので、範囲は素材の外へはみ出してかまいません。

CPU の経路では、BGRA の順に並んだ 8 ビットの素材から、BGRA の 8 ビットの出力を作ります。

```csharp
using var cpu = new CpuTileConvolver();
cpu.Convolve(source, sourceX, sourceY, sourceWidth, sourceHeight, spectrum, plan, output, gain, null);
```

`sourceX` と `sourceY` は素材の左上の座標で、畳み込む範囲と同じ座標系で渡します。`sourceWidth` と `sourceHeight` は素材の幅と高さです。`source` と `output` は `byte[]` で、画素を行ごとに隙間なく並べます。長さは、画素数 × 4 バイト以上です。出力は畳み込む範囲の大きさで、左上が範囲の左上に当たります。`gain` は出力に掛ける倍率で、以下ではゲインと呼びます。Wave Optics の「利得」に当たります。最後の引数 `null` は、ゲインを掛ける前の値を保存しない指定です。保存は、[CPU の経路](#3-cpu-の経路)で説明します。

GPU の経路では、素材と出力のテクスチャを使う処理を、ComputeWeave のコンテキストに記録します。ComputeWeave では、`GraphicsDevice` から作った `ComputeContext` に、計算シェーダーの実行を記録します。

```csharp
using var gpu = new GpuTileConvolver(device);
gpu.Upload(spectrum);
var job = gpu.Prepare(plan, sourceX, sourceY, sourceWidth, sourceHeight, gain, samples, false);
using (var context = device.CreateComputeContext())
{
    GpuTileConvolver.Record(
        in context, sourceTexture, outputTexture, gpu.Tiles, gpu.Twiddles, gpu.Spectrum,
        gpu.Report, gpu.Samples, gpu.StoreFor(job), job);
}

var measurements = new ConvolutionMeasurement[GpuTileCheck.MeasurementCount(samples.Length)];
GpuTileCheck.Evaluate(gpu.ReadReport(job), job, samples, spectrum.Kernel, measurements);
```

`device` は ComputeWeave の `GraphicsDevice` です。`sourceTexture` と `outputTexture` は、どちらも `ReadWriteTexture2D<Bgra32, Float4>` です。素材のテクスチャは `sourceWidth` × `sourceHeight` 画素、出力のテクスチャは畳み込む範囲と同じ大きさにします。`gpu.Tiles`、`gpu.Twiddles`、`gpu.Spectrum`、`gpu.Report`、`gpu.Samples` の 5 つは、`GpuTileConvolver` が確保した資源で、そのまま `Record` に渡します。

スペクトルは、`plan` と同じ T と r で `Update` してから `Upload` し、その後に `Prepare` を呼びます。`using` ブロックを抜けるときに、記録した処理が GPU へ送られます。`ReadReport` は、その後に呼びます。

`Prepare` の最後の引数は、ゲインを掛ける前の値を保存するかどうかです。`true` を渡すと、`StoreFor(job)` は保存用のバッファーを返します。`false` を渡すと、代わりのバッファーを返します。代わりのバッファーは、`Record` の保存用の引数に渡すだけで、中身は使いません。大きさは 16 バイトです。保存を求めたときは、`ReadStore` で保存した値も読み戻せます。保存は、[GPU の経路](#4-gpu-の経路)で説明します。

`samples` は、検査で値を抜き取る出力の位置を並べた `Int2` の配列かスパンです。最大 16 か所で、畳み込む範囲の左上を原点とした座標で渡します。`GpuTileCheck.Evaluate` は、`ReadReport` で読み戻した値から検査を作り、`measurements` に書きます。読み戻す値は、[検査の材料](#5-検査の材料と検査)です。`measurements` の長さは、`GpuTileCheck.MeasurementCount` で求めます。`spectrum.Kernel` は、和で割った後のカーネルです。`Evaluate` は、これを使って、抜き取った位置の参照値を求めます。

ComputeWeave の `[ComputePipelineHost]` を付けた `partial` クラスで、`[ComputePipeline]` を付けたメソッドから `Record` を呼ぶこともできます。メソッドの先頭の引数は、`in ComputeContext` にします。`Record` に渡す資源は、すべて、そのメソッドの引数として宣言します。`GpuTileJob` は資源ではないので、`[ComputeResource]` を付けずに、通常の引数として宣言します。Wave Optics は、この形で使っています。実例は、[WaveOpticsPipelineHost.cs](../WaveOptics/Rendering/WaveOpticsPipelineHost.cs) にあります。この形には `using` ブロックが無く、生成されたメソッドは `ComputeSubmission` を返します。`ComputeSubmission` の `Wait` を呼んでから、`ReadReport` や `ReadStore` を呼びます。資源の引数には、次の表のアクセスで `[ComputeResource]` を付けます。

| 資源 | アクセス |
|---|---|
| 素材のテクスチャ、出力のテクスチャ、`Tiles`、`Report`、`StoreFor(job)` の戻り値 | `ComputeResourceAccess.ReadWrite` |
| `Twiddles`、`Spectrum`、`Samples` | `ComputeResourceAccess.Read` |

自己試験は、GPU の経路を初めて使う前に行います。

```csharp
var measurements = new ConvolutionMeasurement[SpectralSelfTest.MeasurementCount];
var count = SpectralSelfTest.Run(device, maximumRadius, measurements);
```

`maximumRadius` は、プラグインが使う最大のカーネルの半径です。戻り値の `count` は、`measurements` の先頭から書き込んだ件数です。この `count` 件が、自己試験の検査です。Wave Optics は、[WaveOpticsCompute.cs](../WaveOptics/Rendering/WaveOpticsCompute.cs) で、これを YMM4-ComputeGuard の検査へ変換して渡しています。

## 主な機能

### 1. タイルに分けた畳み込み

畳み込む範囲を、一辺 T 画素の正方形のタイルに分けます。T は 2 のべき乗で、`TilePlan.SelectSize` がカーネルの半径から次の規則で決めます。

| 半径 | T | 1 枚のタイルが出力する範囲 |
|---|---|---|
| 0〜23 | 128 | 一辺 128 - 2r 画素 |
| 24〜255 | 512 | 一辺 512 - 2r 画素 |

`TilePlan.Create` に T を直接渡すと、64 と 256 も使えます。どの T でも、2r は T より小さくなければなりません。

1 枚のタイルが出力する範囲は、一辺 T - 2r 画素です。タイルは、この範囲を上下左右に r 画素ずつ広げた、T × T 画素の範囲の素材を読みます。畳み込む範囲の端にあって、出力が T - 2r 画素に満たないタイルも、T × T 画素を読みます。タイルごとに 2 次元の高速フーリエ変換を求め、カーネルのスペクトルを掛け、逆変換します。この計算は巡回畳み込みです。巡回畳み込みは、タイルの右端の次に左端が、下端の次に上端が続くとみなして畳み込む計算です。そのため、縁から r 画素以内の値は、反対側の縁にある素材の影響を受けます。その r 画素の幅の値を捨て、中央の (T - 2r) × (T - 2r) 画素だけを出力します。この方法をオーバーラップセーブ法と呼びます。

畳み込む範囲全体を 1 回で変換せずにタイルに分けるのは、作業領域の大きさと誤差の上限を、範囲の大きさによらず決めるためです。タイルどうしは互いに独立しているので、どの順に計算しても結果は同じです。

変換は、基数 2 の時間間引きの高速フーリエ変換です。行に変換をかけてから列に変換をかけ、逆変換は列、行の順に行います。変換に使う回転因子は、j を 0 から T / 2 - 1 までの整数として、exp(-2πi j / T) で表される値です。この値を並べた表を作ります。表の値は、倍精度の `Math.SinCos` で求めた値を float に丸めたものです。CPU と GPU は同じ表を使い、GPU では三角関数を使いません。

カーネルのスペクトルは、カーネルを T × T の配列に置いて、2 次元の高速フーリエ変換をかけたものです。倍精度で求めてから、float に丸めます。高速フーリエ変換で求まるのは数学の定義の畳み込みなので、式 (1) の向きにそろえるために、カーネルの値 k(d) を位置 -d に置きます。位置は T を周期として折り返し、残りは 0 にします。値は、GPU の列の計算で連続して読めるよう、列ごとに並べます。

2^-126 は float の正の正規化数の最小値で、0 でなく絶対値がこれより小さい値を非正規化数と呼びます。回転因子とスペクトルの非正規化数は、符号を残して 0 にします。GPU は非正規化数を 0 にすることがあるので、CPU の側で先に 0 にそろえておきます。

### 2. 2 つのチャンネルをまとめる複素数

素材の 4 つのチャンネルを、赤と緑、青と不透明度の 2 組に分けます。組の一方を実部、もう一方を虚部とした複素数で変換します。カーネルは実数なので、逆変換の実部と虚部が、そのまま 2 つのチャンネルの畳み込みになります。1 回の複素数の変換で 2 つのチャンネルを計算できます。

### 3. CPU の経路

コンストラクターに渡すスレッド数を N とします。`CpuTileConvolver` は、生成するときに N - 1 本の作業スレッドを作り、`Dispose` するまで使い回します。`Convolve` を呼んだスレッドも計算に加わるので、計算するスレッドは最大で N 本です。タイルは、これらのスレッドに割り当てます。N を渡さないときは、論理プロセッサーの数になります。

1 回の畳み込みで同時に計算するスレッドの数は、次の 3 つのうち最も小さい数です。

- N
- タイルの枚数
- タイルの作業領域の合計が 64 MB を超えない最大のスレッド数

タイルの作業領域は、T × T の 4 チャンネルの float で、16 T² バイトです。そのため、T が 512 のときは 16 スレッド、128 のときは 256 スレッドが上限です。MB は 2^20 バイトです。

計算するスレッドは、それぞれ 1 組の作業領域を使います。1 組は、タイル用の 16 T² バイトと、1 行分の配列 2 つ用の 32 T バイトです。作業領域は初めて使うときに確保し、T が変わるまで持ち続けます。T が変わると、すべての作業領域を捨てます。持ち続けるのは同じ T の作業領域だけで、その数は上のスレッド数で抑えられるので、タイルの分は合計で 64 MB 以下です。同じ T の呼び出しが続くあいだは、同時に計算するスレッドが前より増えたときだけ、新しいメモリを確保します。

出力では、畳み込んだ値にゲインを掛け、Direct3D の規則と同じ式で 8 ビットへ変えます。NaN は 0 にし、0〜1 に切り詰め、255 倍して 0.5 を足し、端数を切り捨てます。

ゲインだけを変えるときは、畳み込みをやり直さずに出力できます。そのために、`Convolve` の最後の引数 `convolvedValues` に配列を渡します。渡した配列に、ゲインを掛ける前の値が float で保存されます。保存する値は、画素ごとに R、G、B、A の順の float 4 つで、出力の BGRA とは順が違います。配列の長さは、畳み込む範囲の幅 × 高さ × 4 以上です。

`RenderStored` は、保存した値に別のゲインを掛けて出力し直します。結果は、そのゲインで畳み込みと同時に出力した場合と 1 ビットも違いません。`RenderStored` は、16384 画素を 1 単位として、スレッドに割り当てます。

素材の外にある行と、4 つのチャンネルがすべて 0 の画素だけからなる行は、行の変換を省きます。タイルが読む T × T の範囲のどの行もそうなら、タイルの計算をすべて省き、出力と保存する値に 0 を書きます。どちらも、変換した場合と同じ値になります。

### 4. GPU の経路

`GpuTileConvolver.Record` は、計算シェーダーの実行をコンテキストに記録します。計算シェーダーを 1 回起動することを、ディスパッチと呼びます。まず `ReportResetShader` で、`Report` の先頭にある NaN と無限大の個数を 0 にします。`Report` は、[検査の材料](#5-検査の材料と検査)を書くバッファーです。抜き取る位置があるときは、続けて `GatherShader` で、その周りの素材を集めます。

そのあと、タイルを計算します。作業領域が 16 MB に収まる枚数のタイルをまとめて計算し、このまとまりをバッチと呼びます。1 つのバッチのタイルは、T が 512 のときは 4 枚まで、128 のときは 64 枚までです。バッチごとに、次の 3 回のディスパッチを記録します。

| 順 | シェーダー | 処理 |
|---|---|---|
| 1 | `ForwardRowShader` | 素材を読み、行に変換をかける。素材の和と 2 乗の和も書く |
| 2 | `ColumnShader` | 列に変換をかけ、スペクトルを掛け、列に逆変換をかける |
| 3 | `InverseRowShader` | 行に逆変換をかけ、出力に書く。NaN と無限大の個数、出力の和、抜き取った出力も書く |

1 つのスレッドグループは 256 スレッドで、512 個の値を受け持ちます。以下では、スレッドグループを単にグループと呼びます。値はグループ共有メモリに置きます。`ColumnShader` は、列を転置せずにその場で変換します。

浮動小数点数を計算するシェーダーは、ComputeWeave の `CompileOptions.IeeeStrictness` を付けてコンパイルします。これは、シェーダーのコンパイラーである DXC の `-Gis` に当たり、精度を緩める最適化を許しません。

出力のテクスチャには、ゲインを掛けた値を書きます。`Prepare` の最後の引数に `true` を渡すと、ゲインを掛ける前の値を、畳み込む範囲の 1 画素につき 16 バイトのバッファーに保存します。`RecordStored` は、保存した値に別のゲインを掛けて出力し直します。結果は、そのゲインで畳み込みと同時に出力した場合と 1 ビットも違いません。保存に使うバッファーは、`ReleaseStore` か `Dispose` を呼ぶまで持ち続けます。

### 5. 検査の材料と検査

GPU は、検査の材料を 1 つの `uint` のバッファー（`Report`）に書きます。呼び出し側は、これを `ReadReport` で 1 回で読み戻します。アトミック加算は、複数のスレッドが同じ場所に足しても、足し漏れが起きない加算です。

| 値 | 書くシェーダー | 中身 |
|---|---|---|
| NaN と無限大の個数 | `InverseRowShader` | タイルが逆変換で得た T × T 個の画素のうち、ゲインを掛ける前の 4 つのチャンネルのどれかが NaN か無限大のものの数。どの画素の NaN も GPU の異常を示すので、捨てる縁と、畳み込む範囲の外の画素も数える。指数部のビットで判定し、整数のアトミック加算で数える |
| 素材の和 | `ForwardRowShader` | タイルが出力する範囲のうち、畳み込む範囲の中にある素材の 8 ビットの値の和。チャンネルごと |
| 素材の 2 乗の和 | `ForwardRowShader` | タイルが読む T × T の範囲の素材の、8 ビットの値の 2 乗の和。赤と緑、青と不透明度の 2 組 |
| 出力の和 | `InverseRowShader` | ゲインを掛ける前の出力の値を、スレッドグループの 512 個ずつ、深さ 9 の二分木で足した値。捨てる縁の値と、畳み込む範囲の外の値は 0 として足す |
| 抜き取った出力 | `InverseRowShader` | 抜き取る位置の、ゲインを掛ける前の 4 つのチャンネルの値 |
| 抜き取った近傍 | `GatherShader` | 抜き取る位置の周りの (2r + 1) × (2r + 1) 画素の、素材の 8 ビットの値 |

`GpuTileCheck.Evaluate` は、これらから次の検査を作ります。S は抜き取る位置の数で、最大 16 です。

| 名前 | 測定値 | 参照値 | 許容値 |
|---|---|---|---|
| `nonfinite` | NaN と無限大の個数 | 0 | 0 |
| `sum.red` など 4 件 | 出力の和を、グループの順に倍精度で足した値 | 素材の和を 255 で割った値 | [総和の上限](#8-総和の上限)で導いた値 |
| `spot.red` など S × 4 件 | 抜き取った出力の値 | 抜き取った近傍から `DirectCorrelation` で求めた値 | タイルの誤差の上限（[1 画素の上限](#7-1-画素の上限)）と、参照値の誤差の上限（[参照値の誤差](#9-参照値の誤差)）の和 |

総和の検査は、素材の画素の位置によっては、正常な GPU でも不合格になることがあります。素材の 1 画素は、その画素を中心とする一辺 2r + 1 画素の正方形に含まれる出力の画素に寄与します。

総和の検査の参照値は、畳み込む範囲の中にある素材の和を 255 で割った値です。ある条件が成り立つとき、誤差の無い、ゲインを掛ける前の出力の和は、この参照値の σ 倍と等しくなります。σ は、和で割った後のカーネルの値の和で、丸めのために 1 とわずかに異なります。条件は、値が 0 でない素材の画素ごとに、その画素を中心とする一辺 2r + 1 画素の正方形が、畳み込む範囲に完全に含まれるか、範囲とまったく重ならないことです。これは、等しくなるための十分条件です。

素材の画素の座標を、畳み込む範囲と同じ座標系で (qx, qy) とします。値が 0 でない画素ごとに、次のどちらかの場合に当てはまることが、その条件です。

- 縁から r 画素以上内側にある: `regionX` + r ≤ qx ≤ `regionX` + `regionWidth` - 1 - r、かつ `regionY` + r ≤ qy ≤ `regionY` + `regionHeight` - 1 - r。
- 範囲の外で、縁から r 画素を超えて離れている: qx < `regionX` - r、qx > `regionX` + `regionWidth` - 1 + r、qy < `regionY` - r、qy > `regionY` + `regionHeight` - 1 + r のどれか。

上の 2 つの場合のどちらにも当てはまらない画素があると、その画素の値の一部が、範囲の外へ出るか、範囲の外から入ることがあります。カーネルの値が 0 でない位置を通って、出入りするためです。この出入りの分は、許容値に含めていません。そのため、正常な GPU でも、総和の検査で不合格になることがあります。畳み込む範囲は、この条件を満たすように決めてください。

許容値は、[総和の上限](#8-総和の上限)の式で求めます。条件を満たすときの、計算した出力の和と参照値の差は、σ が 1 からずれる分と、計算で生じる分です。式の最後の項が前者を、それより前の項が後者を見込んでいます。

### 6. 自己試験

`SpectralSelfTest.Run` は、T が 128 と 512 のそれぞれで次の 2 つの場面を GPU で計算し、検査を引数の `measurements` に書き込みます。戻り値は、書き込んだ件数です。`measurements` には、`SpectralSelfTest.MeasurementCount`（280）件以上の長さが要ります。

1. 半径 3 のカーネルで、2 × 2 枚のタイルにまたがる模様を 2 回畳み込みます。2 回の結果でビットが違う値の個数を、`selftest.determinism` の測定値にします。全画素の値を `DirectCorrelation` の値と比べ、差を誤差の上限で割った値の最大を、`selftest.full` の測定値にします。1 回目の結果からは、[検査の材料と検査](#5-検査の材料と検査)の表と同じ検査も作ります。
2. 半径は、T が 128 のときは `maximumRadius` と 23 の小さいほう、512 のときは `maximumRadius` と 255 の小さいほうにします。この半径のカーネルで、模様を 1 回畳み込み、[検査の材料と検査](#5-検査の材料と検査)の表と同じ検査を作ります。23 は、`TilePlan.SelectSize` が T に 128 を選ぶ半径の上限です。255 は、本ライブラリが扱える半径の上限です。

`selftest.determinism` は測定値が 0 のときだけ、`selftest.full` は測定値が 1 以下のときだけ合格です。`maximumRadius` が 3 より小さいと、`ArgumentOutOfRangeException` を投げます。

模様には、値が 0 の領域、不透明な細い線、さまざまな不透明度の画素を入れます。カーネルは、左右にも上下にも非対称な形にします。抜き取る位置は、四隅と中央の 5 か所、タイルの継ぎ目の両側の 2 か所、決まった式で決めた 9 か所です。全画素の比較に小さなカーネルを使うのは、倍精度の直接の計算を軽く保つためです。高速フーリエ変換の各段の計算はカーネルの大きさによらないので、小さなカーネルでも変換のすべての段を通ります。

## 誤差の上限

ここでは、float で計算した畳み込みの値と、厳密な値との差の上限を導きます。差は素材の 2 ノルムに対する相対誤差で追い、1 タイル、1 画素、総和の順に上限を求めます。

### 前提

上限は次の前提の上で成り立ちます。

| 前提 | 中身 |
|---|---|
| GPU の演算 | [Direct3D 11 の浮動小数点数の規則](https://learn.microsoft.com/en-us/windows/win32/direct3d11/floating-point-rules)に従う。加算、減算、乗算の相対誤差は 2^-23 未満。演算の結果が非正規化数になると、符号を残して 0 にする |
| CPU の演算 | IEEE 754 の最も近い値への丸めに従い、相対誤差は 2^-24 以下 |
| 倍精度の演算 | IEEE 754 の最も近い値への丸めに従い、相対誤差は 2^-53 以下 |
| 融合演算 | 掛け算と足し算を 1 つの演算にまとめない。GPU のシェーダーは `-Gis` でコンパイルし、CPU の側は .NET の JIT がまとめないものとする |
| 8 ビットから float への変換 | 255 で割った値を正しく丸める。相対誤差は 2^-24 以下。[変換の規則](https://learn.microsoft.com/en-us/windows/win32/direct3d10/d3d10-graphics-programming-guide-resources-data-conversion)は許容誤差を書かないので、この丸めを前提に置く |
| `Math.SinCos` | 返す値の誤差は、各成分で 2^-51 以下 |
| カーネル | 値はすべて 0 以上で、和で割って 1 にそろえてある。実際の和は 1 からわずかにずれる |

カーネルが 0 以上で和が 1 であるという前提から、スペクトルの絶対値はどこでも 1 以下になり、カーネルの 2 ノルムも 1 以下になります。実際の和は 1 から γ_ker までずれます。γ_ker は、次の記号の表で定義します。このずれの扱いは、[式に入れていない誤差と上限の余裕](#10-式に入れていない誤差と上限の余裕)で説明します。

### 記号

| 記号 | 意味 |
|---|---|
| u | 1 回の演算の相対誤差の上限。GPU では 2^-23、CPU では 2^-24。倍精度の演算では 2^-53 |
| L | log₂T |
| γ_n(ε) | n ε / (1 - n ε)。1 回の相対誤差が ε 以下の丸めを n 回重ねたときの、相対誤差の上限 |
| μ | float の回転因子の誤差の上限 |
| κ | float のスペクトルの誤差の上限 |
| ‖x‖ | 素材の値を 255 で割った値 x の、タイルが読む T × T の 2 ノルム。赤と緑、青と不透明度の組ごとに求める |
| x̂ | float に変えた後の素材 |
| n_k | カーネルの値の数 |
| γ_ker | γ_(n_k+1)(2^-53)。`DirectCorrelation` の丸めの回数の根拠は[参照値の誤差](#9-参照値の誤差)に、カーネルを和で割る丸めの根拠は[式に入れていない誤差と上限の余裕](#10-式に入れていない誤差と上限の余裕)にあります |

μ_d、η_d、α_d の添字 d は、倍精度（double）を表します。ほかの記号は、各節で導くときに説明します。T は[タイルに分けた畳み込み](#1-タイルに分けた畳み込み)で、r は概要で定義しています。

### 1. 回転因子とスペクトル

回転因子は exp(-2πi j / T) です。角度が δ ずれると、回転因子は複素数の絶対値で δ 以下だけずれます。倍精度で求めるとき、角度の誤差は π × 2^-51 以下とし、`Math.SinCos` の誤差は複素数の絶対値で √2 × 2^-51 以下とします。倍精度の回転因子の誤差 μ_d は、この 2 つの和です。

```
μ_d = (π + √2) × 2^-51
```

角度の誤差の実際の値は、π × 2^-51 より小さくなります。これは、[式に入れていない誤差と上限の余裕](#10-式に入れていない誤差と上限の余裕)で説明します。float に丸めると、誤差は次の μ 以下になります。

```
μ = 2^-24 (1 + μ_d) + μ_d
```

回転因子の成分は、0 でないとき絶対値が約 6 × 10^-17 以上で、2^-126 より大きいので、μ には、非正規化数を 0 にそろえる分を入れません。

スペクトルは、倍精度の 2L 段の変換で求めます。この変換の相対誤差の上限を α_d とします。α_d は、[変換の 1 段](#2-変換の-1-段)と[2 次元の変換](#3-2-次元の変換)の式で、u を 2^-53 に、μ を μ_d に置き換えた値です。

```
η_d = (1 + 2^-53)(μ_d + (1 + μ_d) √2 γ_2(2^-53)) + 2^-53
α_d = (1 + η_d)^(2L) - 1
```

T × T の 2 次元の変換は、2 ノルムを T 倍にします。カーネルの 2 ノルムは 1 以下なので、倍精度のスペクトルの各値の絶対誤差は α_d T 以下です。倍精度のスペクトルの絶対値は 1 + α_d T 以下なので、float に丸めると、2^-24 (1 + α_d T) 以下の誤差が加わります。スペクトルの値のうち、非正規化数を 0 にそろえた値では、実部と虚部がそれぞれ 2^-126 未満だけ変わるので、複素数の絶対値で √2 × 2^-126 未満の誤差が加わります。これらを足して、次の κ を得ます。

```
κ = 2^-24 (1 + α_d T) + α_d T + √2 × 2^-126
```

### 2. 変換の 1 段

変換の 1 段では、2 つの値 v₀ と v₁ の組ごとに、v₀ + w v₁ と v₀ - w v₁ を求めます。w は回転因子で、この計算をバタフライと呼びます。m を √2 γ_2(u) とすると、w × v₁ の複素数の掛け算の相対誤差は m 以下です。回転因子の誤差を加えると、この相対誤差は μ + (1 + μ) m 以下です。最後の加算と減算の丸めを加えると、1 段の出力の誤差の 2 ノルムは、正確な出力の 2 ノルムに対して次の η 以下です。

```
η = (1 + u)(μ + (1 + μ) m) + u
```

### 3. 2 次元の変換

2 次元の変換は 2L 段です。各段は、正確に計算すれば、2 ノルムをちょうど √2 倍にします。そのため、s 段目までの相対誤差を e_s とすると、1 + e_(s+1) ≤ (1 + η)(1 + e_s) が成り立ちます。変換全体の相対誤差は、次の α 以下です。

```
α = (1 + η)^(2L) - 1
```

### 4. スペクトルとの掛け算

変換した値 X に、スペクトル K を掛けます。K の絶対値は 1 以下で、float のスペクトルの誤差は κ 以下です。複素数の掛け算の丸めを加えると、掛けた結果の誤差の 2 ノルムは、正確な X の 2 ノルムに対して次の c 以下です。

```
c = α (1 + κ)(1 + m) + κ (1 + m) + m
```

### 5. 逆変換と 1 タイルの上限

逆変換も 2L 段で、相対誤差は α 以下です。最後に掛ける 1 / T² は 2 のべき乗なので、結果が非正規化数になる場合を除いて丸めの誤差がありません。順変換は 2 ノルムを T 倍にし、逆変換と 1 / T² を合わせると 1 / T 倍になるので、2 つの倍率は打ち消し合います。そのため、float の計算が x̂ に対して生む誤差の 2 ノルムは、x̂ の 2 ノルムに、次の b を掛けた値以下です。

```
b = c + α (1 + c)
```

‖x̂‖ は、変える前の ‖x‖ の (1 + 2^-24) 倍以下です。素材を float に変える丸めは、スペクトルの絶対値が 1 以下なので、出力に 2^-24 ‖x‖ 以下の差を生みます。したがって、出力の誤差は b (1 + 2^-24) ‖x‖ + 2^-24 ‖x‖ 以下で、1 タイルの相対の上限 B は次のとおりです。

```
B = b + 2^-24 (1 + b)
```

### 6. 0 にされる値

GPU は、演算の結果が非正規化数になると、その値を 0 にします。1 回で値が変わる量は 2^-126 未満です。1 段で、1 つの複素数の実部と虚部は、それぞれ最大 4 回の演算の結果になります。そのため、1 段で 1 つの複素数が受ける変化は 4√2 × 2^-126 未満で、タイルの T² 個の値の 2 ノルムでは 4√2 × T × 2^-126 未満です。

どの段で生じた変化も、出力に届くまでに大きくなりません。順変換の s 段目で生じた変化は、残りの段と逆変換で (√2)^(4L - s) 倍になり、最後の 1 / T² を掛けると 2^(-s/2) 倍以下になります。掛け算で生じた変化は出力で 1 / T 倍になり、逆変換の段と最後の倍率で生じた変化は 1 倍以下です。後の段の丸めとスペクトルの絶対値で変化が増える分は、合わせて 2 倍未満です。

段の数は、順変換と逆変換で 4L です。これに、掛け算と最後の倍率の 2 段を加えて、4L + 2 段になります。したがって、出力の誤差の 2 ノルムへの寄与は、次の F 以下です。

```
F = 2 (4L + 2) × 4√2 × T × 2^-126
```

`ConvolutionBound.FlushedOperations` は、2^-126 に掛ける係数を整数に切り上げた値を返します。T が 512 のとき F は約 2.6 × 10^-33 で、8 ビットの値の 1 階調分にあたる 1/255 に比べて無視できる大きさです。CPU は 0 にしませんが、非正規化数の範囲の丸めの誤差は 1 回で 2^-150 以下なので、同じ式で押さえられます。

### 7. 1 画素の上限

1 画素の各チャンネルの誤差は、出力の誤差の 2 ノルムを超えません。したがって、次の式が成り立ちます。

```
|ŷ - y| ≤ B ‖x‖ + F
```

ŷ は、ゲインを掛ける前の、float で計算した値です。y は、数学的に厳密に求めた値です。式 (1) の src に x を、k に和で割った後のカーネルを入れて求めます。和で割った後のカーネルは、`KernelSpectrum.Kernel` で読めます。`ConvolutionBound.Absolute` が、上の式の右辺を返します。

素材の 8 ビットの値がすべて 255 のタイルでは、255 で割った値がすべて 1 になり、‖x‖ は最大の √2 T になります。B ‖x‖ + F は、255 で割った値に対する誤差の上限です。255 倍すると、8 ビットの値の 1 階調を 1 とする値になります。B ‖x‖ + F の ‖x‖ に √2 T を入れて 255 倍し、小数第 2 位まで切り上げた値を、T ごとに次の表に示します。切り上げるので、表の値も上限のままです。

| T | GPU の経路（階調） | CPU の経路（階調） |
|---:|---:|---:|
| 64 | 0.30 | 0.17 |
| 128 | 0.69 | 0.39 |
| 256 | 1.57 | 0.88 |
| 512 | 3.52 | 1.97 |

1 つ目の表の値は、ゲインを掛ける前の値に対する上限です。‖x‖ は √2 T を超えないので、どのタイルの上限も 1 つ目の表の値以下です。‖x‖ が √2 T より小さいタイルでは、上限は 1 つ目の表の値より小さくなります。ゲイン g を掛けた値の上限は、ゲインを掛ける前の上限の |g| 倍です。ゲインを掛ける float の丸めと、8 ビットへの丸めによる誤差は、この上限に含みません。

[動作の確認](#動作の確認)で比べるため、B ‖x‖ の ‖x‖ に √2 T を入れて 255 倍し、小数第 3 位までに四捨五入した値を、2 つ目の表に示します。F の項は含みません。F は 10^-30 より小さく、この表の値にも影響しません。2 つ目の表の値は四捨五入しているので、上限としては使えません。

| T | GPU の経路（階調、四捨五入） | CPU の経路（階調、四捨五入） |
|---:|---:|---:|
| 64 | 0.296 | 0.166 |
| 128 | 0.688 | 0.385 |
| 256 | 1.566 | 0.877 |
| 512 | 3.514 | 1.966 |

### 8. 総和の上限

タイル t が出力する画素の数を n_t、タイル t が読む素材の 2 ノルムを ‖x_t‖ とします。出力の誤差の 2 ノルムが B ‖x_t‖ + F 以下なので、n_t 個の誤差の絶対値の和は、√n_t × (B ‖x_t‖ + F) 以下です。これをすべてのタイルで足したものを E とします。E は、赤と緑の組と、青と不透明度の組で別々に求めます。

GPU は、出力の値を 512 個ずつ、深さ 9 の二分木で足します。その誤差は、足す値の絶対値の和に対して γ_9(u) 以下です。木の 511 回の加算で 0 にされる値の分として、グループごとに 511 × 2^-126 を加えます。グループの和は、CPU が倍精度でグループの順に足します。カーネルの和を 1 にそろえるときの丸めの分も加えて、許容値を組み立てます。

G は、畳み込む範囲を覆うすべてのタイルのグループの数で、タイル数 × T² / 512 に等しい数です。Z は、木の加算で 0 にされる値の分です。

参照値は、畳み込む範囲の中にある素材の和を 255 で割った値です。A は、float で計算した出力 ŷ の、範囲全体にわたる絶対値の和の上限です。厳密な出力 y は、カーネルも素材も 0 以上なので、0 以上です。そのため、y の絶対値の和は、y の和に等しくなります。[総和の検査の条件](#5-検査の材料と検査)が成り立つとき、y の和は参照値に 1 + γ_ker を掛けた値を超えません。E は、ŷ と y の差の絶対値の和の上限です。したがって、ŷ の絶対値の和は、参照値に 1 + γ_ker を掛けた値に E を加えた値を超えません。この値を A とします。

次の式では、γ_9 = γ_9(u)、γ_G = γ_G(2^-53) と略記します。γ_ker は、記号の表のとおりです。

```
A = 参照値 × (1 + γ_ker) + E
Z = G × 511 × 2^-126
許容値 = E + γ_9 A + Z + γ_G ((1 + γ_9) A + Z) + 参照値 × γ_ker
```

### 9. 参照値の誤差

`DirectCorrelation` は、n_k 個の積を倍精度で順に足します。1 個の積では、8 ビットの値を 255 で割るときと、カーネルの値を掛けるときの 2 回丸めます。足し算の丸めは、最初の 0 との和を除いた n_k - 1 回です。したがって、1 個の積に重なる丸めは、最大で n_k + 1 回です。素材の値は 1 以下で、積はどれも 0 以上なので、誤差はカーネルの値の和の γ_ker 倍以下です。

カーネルの値の和は 1 + γ_ker 以下なので、誤差は γ_ker (1 + γ_ker) 以下です。このうち γ_ker² は 10^-21 未満です。γ_(n_k+2)(2^-53) と γ_ker の差は 2^-53 以上なので、この誤差は γ_(n_k+2)(2^-53) を超えません。`DirectCorrelation.ErrorBound` は γ_(n_k+2)(2^-53) を返します。この値は、半径 255 のカーネルでも、3 × 10^-11 未満です。

### 10. 式に入れていない誤差と上限の余裕

[1 画素の上限](#7-1-画素の上限)までの式は、カーネルの値の和がちょうど 1 で、式の値を正確に求められるとして導いています。実際には、次の 2 つのずれがあります。

1. `KernelSpectrum` はカーネルの値を倍精度で足して和を求め、各値をその和で割ります。割った後の値の和が 1 からずれる幅は、次の手順で、γ_ker 以下と示せます。
   - 和は、足し算の丸めを n_k - 1 回受けます。真の和に対する計算した和の相対誤差を θ とすると、|θ| ≤ γ_(n_k-1)(2^-53) です。
   - 割り算の丸めの相対誤差は、1 回ごとに 2^-53 以下です。この相対誤差の重み付き平均を ρ とします。ρ の重みは、各値が真の和に占める割合です。重みは 0 以上で、足すと 1 になります。そのため、|ρ| ≤ 2^-53 です。
   - 割った後の和は、(真の和 / 計算した和) × (1 + ρ) です。真の和 / 計算した和 = 1 / (1 + θ) なので、割った後の和は、1 に (1 + ρ) / (1 + θ) を掛けた値です。最悪は θ = -γ_(n_k-1)(2^-53)、ρ = 2^-53 のときで、1 からのずれは次の D 以下です。

   ```
   D = (2^-53 + γ_(n_k-1)(2^-53)) / (1 - γ_(n_k-1)(2^-53))
   ```

   1 つの値に重なる丸めは、足し算の最大 n_k - 1 回と、割り算 1 回で、合わせて n_k 回です。この回数から決まる素朴な上限は、γ_(n_k)(2^-53) です。D は、半径 1 以上で、この素朴な上限をわずかに超えます。超える幅は (n_k × 2^-53)² の程度で、半径 255 でも 10^-21 未満です。γ_(n_k+1)(2^-53) と γ_(n_k)(2^-53) の差は 2^-53 以上あるので、D は γ_(n_k+1)(2^-53) 以下です。この γ_(n_k+1)(2^-53) が、記号の表の γ_ker です。

   そのため、スペクトルの絶対値は 1 + γ_ker 以下としか言えません。カーネルの 2 ノルムも、1 + γ_ker 以下としか言えません。この 2 つの上限を、1 から 1 + γ_ker に替えて b と B を求め直すと、B はほぼ 1 + γ_ker 倍になります。増え方は相対で約 γ_ker で、2γ_ker 未満です。γ_ker は、T が 512 で半径が 255 のときでも 3 × 10^-11 未満です。[総和の上限](#8-総和の上限)と[参照値の誤差](#9-参照値の誤差)の式は、この 1 つ目のずれのうち、カーネルの和が 1 からずれる分を γ_ker として含めています。B が増える分は式に入れず、次の余裕で受けます。
2. 上限と許容値の計算と、検査の比較は倍精度で行うので、丸めで数学的な値からずれます。畳み込む範囲のタイルが 10^6 枚以下なら、ずれは相対で 10^-9 未満です。

一方、回転因子の角度の誤差には、実際の上限より大きい π × 2^-51 を使っています。角度 -2π j / T は、倍精度で計算します。その丸めは π × 2^-53 以下で、倍精度の π の誤差は 1.3 × 10^-16 未満なので、実際の角度の誤差は 4.8 × 10^-16 以下です。π × 2^-51 は約 1.4 × 10^-15 で、実際の上限 4.8 × 10^-16 の約 3 倍です。角度の誤差に実際の上限を使って B を求め直した値を、B' とします。B は、B' より相対で 5.6 × 10^-8 以上大きくなっています。この差を余裕と呼びます。余裕が最小になるのは、T が 64 の GPU の経路で、余裕の大半は、κ の α_d T の項から生じます。

2 つのずれの合計は、2γ_ker が 6 × 10^-11 未満、倍精度の計算の丸めが 10^-9 未満なので、1.1 × 10^-9 未満です。余裕はこの合計の 50 倍を超えるので、上限はずれを含めても成り立ちます。

## 決定論

- タイルどうしは互いに独立しています。CPU の経路では、スレッド数と、どのスレッドがどのタイルを受け持つかを変えても、結果は 1 ビットも変わりません。
- GPU の経路では、同じデバイスで同じ入力を 2 回計算すると、結果は 1 ビットも変わりません。単体試験と自己試験で確かめています。
- 出力の和は、グループの中では決まった木の形で、グループどうしは CPU が決まった順で足します。NaN と無限大の個数、素材の和と 2 乗の和は、整数のアトミック加算で数えます。整数の加算は順序に左右されないので、毎回同じ値になります。
- CPU の経路と GPU の経路は、結果が 1 ビット単位では一致するとは限りません。Direct3D の規則では、GPU は加算、減算、乗算の結果を、最も近い値へ丸める代わりに切り捨てることも許されているためです。2 つの経路の差は、それぞれの誤差の上限の和を超えません。

## メモリ

GPU の経路で `GpuTileConvolver` が確保するメモリは、次のとおりです。素材と出力のテクスチャは、呼び出し側が用意します。G は、畳み込む範囲を覆うすべてのタイルのグループの数で、タイル数 × T² / 512 に等しい数です。S は、抜き取る位置の数です。

| 資源 | 大きさ |
|---|---|
| タイルのバッチ | 16 MB 以下 |
| スペクトル | 8 T² バイト。T が 512 のとき 2 MB |
| 回転因子 | 4 T バイト |
| 検査の材料 | (1 + 10 G + 4 S + S (2r + 1)²) × 4 バイト。CPU から読める写しを含めて、その 2 倍 |
| 抜き取る位置 | 128 バイト |
| 保存しないときの代わりのバッファー | 16 バイト |
| 保存した値 | 畳み込む範囲の 1 画素につき 16 バイト。保存を求めたときだけ |

タイルのバッチと検査の材料は、それまでで最も大きかった大きさを持ち続けます。

CPU の経路で `CpuTileConvolver` が持つメモリは、計算したスレッドごとに 16 T² + 32 T バイトです。タイルの分の合計は 64 MB 以下で、T が変わると捨てます。`WorkingBytes` は、いま持っている作業領域のバイト数を返します。ほかに、高速フーリエ変換の要素の並べ替えに使う順序の表を、それまでで最も大きかった T について 4 T バイト持ちます。素材、出力、保存する値の配列は、呼び出し側が用意します。

## 制限事項

- 検査で見つけられるのは、NaN と無限大、総和、16 か所までの抜き取りに表れた誤りだけです。抜き取った位置の外の誤りで、総和が変わらないものは見逃します。
- 総和の検査には条件があります。条件を外れる素材の画素があると、正常な GPU でも総和の検査で不合格になることがあります。条件は、[検査の材料と検査](#5-検査の材料と検査)にあります。
- カーネルの値は 0 以上でなければなりません。負の値を含むカーネルでは、スペクトルの絶対値が 1 を超えることがあり、上限の導出が成り立たないためです。`KernelSpectrum.Update` は、負の値があると `ArgumentOutOfRangeException` を投げます。
- 誤差の上限は、[前提](#前提)が成り立つときの値です。`Math.SinCos` の精度は .NET の仕様で保証されていないため、前提として置いています。
- 型はどれも 1 つのスレッドから使う前提です。`CpuTileConvolver` の呼び出しを、複数のスレッドから同時に行わないでください。

## 動作の確認

単体試験は xUnit v3 と Microsoft.Testing.Platform で動きます。Wave Optics のリポジトリの直下で、次のコマンドを実行します。

```bash
dotnet test SpectralConvolution/SpectralConvolution.Tests/SpectralConvolution.Tests.csproj -c Release
```

単体試験は次のことを確かめます。

- CPU と GPU の結果が、`DirectCorrelation` の値との差で上限に収まること。素材の 8 ビットの値がすべて 255 の場面も含みます。
- GPU の命令を CPU で実行するソフトウェア アダプターである Microsoft Basic Render Driver でも、上限に収まり、検査に合格すること
- CPU の結果がスレッド数によらないこと。GPU の結果が 2 回で 1 ビットも違わないこと
- 保存した値から描いた結果が、畳み込みと同時に出力した結果と 1 ビットも違わないこと
- CPU の経路で持ち続ける作業領域が、計算したスレッドの分だけで、T が変わると捨てられること
- GPU に渡すスペクトルを 1.0005 倍すると、総和の検査で不合格になること
- スペクトルの虚部の符号を反転すると、抜き取りの検査で不合格になり、総和の検査は合格のままであること。この反転は、カーネルの上下と左右を反転することに当たります。
- スペクトルに NaN を入れると、`nonfinite` の検査で不合格になること
- ‖x‖ に √2 T を入れた B ‖x‖ を 255 倍して、小数第 3 位までに四捨五入した値が、[1 画素の上限](#7-1-画素の上限)の 2 つ目の表の値と一致すること。F の項は含みません。
